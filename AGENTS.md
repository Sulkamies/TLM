> This file lives at the repository root as `AGENTS.md`, the standard location that most AI coding agents read automatically. Tool-specific files (e.g. `CLAUDE.md`, `.github/copilot-instructions.md`) MUST only point to this file and MUST NOT add rules of their own.

> **Every agent working on this project MUST read this entire file before writing any code, and MUST re-read it whenever it changes.**
> The rules here are binding. If a rule conflicts with your own judgment, follow the rule and raise the conflict (see §10). If a rule conflicts with a direct instruction from a human team member, the human wins, and the agent records the deviation in `docs/DEVIATIONS.md`.

The key words **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT** and **MAY** follow RFC 2119.

Items marked **[ASSUMPTION]** are defaults that the team has not yet confirmed. They are binding until a human changes them.

## 1. What we are building

A user submits:

1. **An input file** describing a house floor plan, in one of these formats: **PNG, JPEG, PDF** (raster or vector drawing) or **IFC** (a BIM model).
2. **A question** in natural language and in **any of several languages** (at least English, German and Finnish), with a **numeric answer**, for example *"How many bedrooms are there?"*, *"Wie groß ist die Küche?"*, *"Onko talossa saunaa?"*. Yes/no questions are answered with **1.0 (yes) or 0.0 (no)**.

The system returns **a floating-point number** with its unit (e.g. `count`, `m`, `m2`, `m3`, `boolean`) and supporting metadata, or a structured explanation of why it cannot produce one.

### 1.1 Pipeline

```
                ┌──────────────────────┐
 file+question  │  ORCHESTRATOR (A0)   │  final Answer (float) / ErrorEnvelope
 ─────────────► │  entry point, routing│ ─────────────────────────────►
                └──────────┬───────────┘
                           │ 1.
                           ▼
                ┌──────────────────────┐
                │ INPUT VALIDATOR (A1) │──► LLM API (PNG/JPEG/PDF only)
                └──────────┬───────────┘
                           │ ValidationResult (is_valid = false → STOP)
             ┌─────────────┴──────────────┐   2. run in parallel
             ▼                            ▼
 ┌──────────────────────┐    ┌──────────────────────────┐
 │ QUESTION INTERPRETER │    │  BLUEPRINT ANALYZER (A3) │
 │ (A2) ──► LLM API     │    │  raster → image recognition
 │                      │    │  IFC    → model parsing  │
 └──────────┬───────────┘    └────────────┬─────────────┘
            │ ParsedQuestion              │ BlueprintAnalysis
            └─────────────┬───────────────┘
                          ▼  3.
                ┌──────────────────────┐
                │ ANSWER REASONER (A4) │  deterministic computation
                └──────────┬───────────┘
                           │ Answer
                           ▼
                      ORCHESTRATOR
```

Agent **A5 (QA & Integration Tester)** works across all components and owns the end-to-end tests.

**Core design principles**

1. **Separation of what is seen from what is asked.** The Blueprint Analyzer describes *what is in the plan* and never sees the question. The Question Interpreter describes *what is being asked* and never sees the plan. Only the Answer Reasoner combines the two.
2. **One plan model for all formats.** PNG, JPEG, PDF and IFC all produce the **same `BlueprintAnalysis` contract**. Nothing downstream of A3 may branch on the input format.
3. **LLMs interpret; code computes.** LLMs may classify, extract and parse. **The final numeric answer is always computed by deterministic code** in A4, never generated by an LLM.

## 2. Agent roles, people and ownership

The team has **4 human members**. Humans are not assigned to fixed agents: any human may launch an agent in any role.

- **R2.0a** Every agent session MUST work in **exactly one role** (A0–A5), declared at the start of the session and in its branch name (§9). An agent MUST NOT switch roles within a session or a branch.
- **R2.0b** The human who launched an agent is responsible for that agent's output and is its reviewer of first resort.
- **R2.0c** Two agents in the same role MAY work in parallel, but only on separate branches and separate tasks. Coordinate through `docs/TASKS.md`: claim a task with your role, the human's name and the date before you start it.

## 3. Technical baseline

- **R3.1** The default language is **Python 3.11+**.
- **R3.2** Data contracts are **Pydantic v2** models in `src/blueprint_qa/contracts/`. They are the *only* way data crosses a component boundary. Never pass raw dicts, tuples or untyped JSON between components.
- **R3.3** **Stack variation is allowed, with conditions.** A component MAY use a different language, framework or runtime (for example a separate service, or a Node or C++ tool) if **all** of these hold:
  1. It is approved by a human, and recorded in `docs/DECISIONS.md` with the reason.
  2. It consumes and produces the contracts as **JSON** that validates against the generated JSON Schemas in `src/blueprint_qa/contracts/schema/` (A0 generates them from the Pydantic models and MUST NOT hand-edit them).
  3. It is wrapped by a thin Python adapter inside the owning component that exposes the **exact entry point** defined in §6, so A0 and A5 see no difference.
  4. It can be run and tested in CI without manual setup.
- **R3.4** Python dependencies are declared in the single root `pyproject.toml` (a shared file, see §4.3). Pin to a minor version range (`foo>=1.4,<1.5`).
- **R3.5** Formatting and linting: `ruff format` and `ruff check` MUST pass. Type checking: `mypy --strict` MUST pass on `src/`.
- **R3.6** Each component exposes **exactly one public entry point** (§6). Everything else is private.
- **R3.7** Components MUST be **stateless** between requests. Loading models once at startup is allowed. Caching user data across requests is not.
- **R3.8** Secrets (API keys) come from environment variables only, listed in `.env.example`. Never commit, log or echo them in an error message.
- **R3.9** **No hard limits** are imposed on processing time or input size. However, every limit-like parameter (timeouts, retries, confidence thresholds) MUST be **configurable** in `config/` and MUST NOT be hard-coded.

## 4. Contracts are law

`src/blueprint_qa/contracts/` is the single source of truth for inter-component data. The schemas below are the authoritative **v1.2.0** specification. The code MUST match this document exactly.

### 4.1 Global conventions

| Topic | Rule |
|-------|------|
| Field naming | `snake_case` in Python and JSON |
| Enums | `UPPER_SNAKE_CASE` string values |
| IDs | `request_id`: UUID4 string, created by A0 and passed through **unchanged**. Element IDs: `<type>_<n>` (e.g. `room_3`, `door_1`), unique within one `BlueprintAnalysis`. For IFC input, the IFC `GlobalId` goes in `source_ref` and the element `id` still follows `<type>_<n>` |
| Coordinate spaces | `BlueprintAnalysis.coordinate_space` is either `PIXEL` (raster/PDF: origin top-left of the normalized image, x right, y down) or `METRIC` (IFC: plan coordinates in metres, x/y in the storey plane). Polygons are lists of `[x, y]` floats, implicitly closed, clockwise in their own space |
| Units | All internal physical values are **SI**: m, m², m³. Conversion to other units happens **only** in A4 |
| Unknown values | `null`/`None`. Never guess silently and never use sentinel values (`-1`, `0`, `NaN`) |
| Confidence | `float` in `[0.0, 1.0]` on every inferred value. IFC-derived facts use `1.0` unless the IFC data itself is inconsistent |
| Time | ISO 8601 UTC |
| Versioning | Every top-level contract carries `schema_version: str` (semver) |

### 4.2 Contract definitions (v1.2.0)

```python
# src/blueprint_qa/contracts/common.py
Confidence = Annotated[float, Field(ge=0.0, le=1.0)]   # type of every `confidence` field (§4.1); since v1.0.1
class Stage(str, Enum):
    ORCHESTRATOR = "ORCHESTRATOR"; VALIDATION = "VALIDATION"; QUESTION = "QUESTION"
    ANALYSIS = "ANALYSIS"; REASONING = "REASONING"

class InputFormat(str, Enum):
    PNG = "PNG"; JPEG = "JPEG"; PDF = "PDF"; IFC = "IFC"

class ErrorEnvelope(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    stage: Stage
    code: str                       # from the registry in §5
    message: str                    # safe to show to the end user
    retryable: bool
    details: dict[str, str] = {}    # internal debug info; never user data or secrets

# src/blueprint_qa/contracts/vocabulary.py
# THE single place defining what a plan can contain (A3 emits only these, A2 asks only
# about these). Each value also has a one-line meaning in DESCRIPTIONS; VOCABULARIES
# maps name -> values. A unit test enforces 1:1 coverage. Change via §4.3 only.
class RoomType(str, Enum):
    BEDROOM = "BEDROOM"; BATHROOM = "BATHROOM"; TOILET = "TOILET"; KITCHEN = "KITCHEN"
    LIVING_ROOM = "LIVING_ROOM"; DINING_ROOM = "DINING_ROOM"; HALLWAY = "HALLWAY"
    GARAGE = "GARAGE"; STORAGE = "STORAGE"; CLOSET = "CLOSET"; LAUNDRY = "LAUNDRY"
    SAUNA = "SAUNA"; BALCONY = "BALCONY"; OFFICE = "OFFICE"; TECHNICAL = "TECHNICAL"
    OTHER = "OTHER"; UNKNOWN = "UNKNOWN"

class FixtureType(str, Enum):           # since v1.1.0 (change 001)
    TOILET = "TOILET"; SINK = "SINK"; SHOWER = "SHOWER"; BATHTUB = "BATHTUB"
    SAUNA_BENCH = "SAUNA_BENCH"; OTHER = "OTHER"

class StoreyLevel(str, Enum):           # since v1.1.0 (change 004)
    BASEMENT = "BASEMENT"; GROUND = "GROUND"; UPPER = "UPPER"
    UPPER_1 = "UPPER_1"; UPPER_2 = "UPPER_2"; UPPER_3 = "UPPER_3"; ATTIC = "ATTIC"

EntityCategory = Literal["ROOM", "DOOR", "WINDOW", "WALL", "STAIR", "STOREY", "WHOLE_PLAN", "FIXTURE"]
OpeningKind = Literal["DOOR", "WINDOW", "OPENING"]
DESCRIPTIONS: Mapping[str, Mapping[str, str]]   # vocabulary name -> value -> meaning
VOCABULARIES: Mapping[str, tuple[str, ...]]     # vocabulary name -> values, in order

# src/blueprint_qa/contracts/request.py
class PipelineRequest(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    input_bytes: bytes
    input_format: InputFormat       # declared by the caller; A1 verifies it
    filename: str | None = None
    question: str = Field(min_length=1)
    locale_hint: str | None = None  # BCP-47 UI locale if known; A2 detects the real language
    received_at: datetime
    validation_token: str | None = None   # since v1.2.0 (change 006): receipt from an earlier ValidationResult; only A1 reads it

# src/blueprint_qa/contracts/validation.py
class ValidationReason(str, Enum):
    OK = "OK"; NOT_A_BLUEPRINT = "NOT_A_BLUEPRINT"; FORMAT_MISMATCH = "FORMAT_MISMATCH"
    UNREADABLE = "UNREADABLE"; NO_SPATIAL_DATA = "NO_SPATIAL_DATA"   # e.g. IFC without spaces/walls
    MULTI_PAGE_PDF = "MULTI_PAGE_PDF"   # PDFs must have exactly 1 page
    LOW_CONFIDENCE = "LOW_CONFIDENCE"

class PlanImage(BaseModel):
    image_png: bytes                # normalized PNG, EXIF-rotated, NOT resized
    width_px: int
    height_px: int

class ValidationResult(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    is_valid: bool
    reason: ValidationReason
    confidence: Confidence
    input_format: InputFormat       # verified format (from magic bytes / header)
    provider: str                   # e.g. "llm:<model-id>:prompt@v3", "local:ifc", "mock"
    plan_image: PlanImage | None    # PNG/JPEG/PDF only; None for IFC or when invalid
    ifc_bytes: bytes | None         # IFC only, passed through unchanged
    ifc_schema: str | None          # e.g. "IFC2X3", "IFC4", "IFC4X3"
    validation_token: str | None = None   # since v1.2.0 (change 006): signed receipt issued by A1 when is_valid; opaque to others

# src/blueprint_qa/contracts/question.py
class Intent(str, Enum):
    COUNT = "COUNT"            # "how many bedrooms"
    AREA = "AREA"              # "area of the kitchen", "total floor area"
    LENGTH = "LENGTH"          # "how long/wide is the living room"
    PERIMETER = "PERIMETER"    # "perimeter of the house"
    HEIGHT = "HEIGHT"          # "ceiling height" (usually IFC only)
    VOLUME = "VOLUME"          # "volume of the garage" (usually IFC only)
    DISTANCE = "DISTANCE"      # "distance from kitchen to front door"
    RATIO = "RATIO"            # "what share of the area is bedrooms"
    EXISTENCE = "EXISTENCE"    # "is there a sauna" → 1.0 / 0.0
    COMPARISON = "COMPARISON"  # "is the kitchen bigger than 10 m²" → 1.0 / 0.0
    UNSUPPORTED = "UNSUPPORTED"   # cannot be answered with a number, e.g. "where is the kitchen"

class Aggregation(str, Enum):
    SINGLE = "SINGLE"; SUM = "SUM"; MAX = "MAX"; MIN = "MIN"; MEAN = "MEAN"

class Comparison(BaseModel):
    measure: Literal["COUNT", "AREA", "LENGTH", "PERIMETER", "HEIGHT", "VOLUME"]
    operator: Literal["GT", "GE", "LT", "LE", "EQ"]
    threshold: float | None             # in SI units (A2 converts); None = compare targets[0] vs targets[1]

class EntityRef(BaseModel):
    category: EntityCategory            # see vocabulary.py
    room_type: RoomType | None = None   # shared enum, see vocabulary.py
    label: str | None = None            # literal text, e.g. "Bedroom 2"
    ordinal: int | None = None          # "the second bedroom"
    storey: str | None = None           # holds a StoreyLevel value (vocabulary.py); A2 enforces it (change 004)
    fixture_type: FixtureType | None = None   # set iff category == "FIXTURE"; since v1.1.0

class ParsedQuestion(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    original_question: str
    language: str                       # detected BCP-47 code, e.g. "en", "de", "fi"
    intent: Intent
    aggregation: Aggregation
    targets: list[EntityRef]            # ≥1; exactly 2 for DISTANCE; numerator+denominator for RATIO
    comparison: Comparison | None       # required iff intent == COMPARISON
    requested_unit: Literal["m", "m2", "m3", "ft", "ft2", "ft3"] | None
    confidence: Confidence
    provider: str                       # "llm:<model-id>:prompt@vN", "local:rules", "mock"
    clarification_needed: str | None

# src/blueprint_qa/contracts/analysis.py   (re-exports RoomType, FixtureType, StoreyLevel from vocabulary.py)
class Scale(BaseModel):
    pixels_per_meter: float | None      # None for METRIC space or unknown scale
    source: Literal["SCALE_BAR", "DIMENSION_TEXT", "KNOWN_OBJECT", "IFC_MODEL", "NONE"]
    confidence: Confidence

class Storey(BaseModel):
    id: str; name: str | None; elevation_m: float | None
    level: StoreyLevel | None = None    # since v1.1.0; A3 maps the storey label/elevation to a level

class Room(BaseModel):
    id: str; storey_id: str | None
    room_type: RoomType
    label_text: str | None              # verbatim, original language (e.g. "MH 2", "Schlafzimmer")
    polygon: list[tuple[float, float]]
    area_m2: float | None
    area_source: Literal["COMPUTED", "LABEL_TEXT", "IFC_PROPERTY"] | None
    height_m: float | None
    source_ref: str | None              # IFC GlobalId, if any
    confidence: Confidence

class Opening(BaseModel):
    id: str; storey_id: str | None
    kind: OpeningKind                   # see vocabulary.py
    position: tuple[float, float]
    width_m: float | None
    connects: list[str]                 # room ids; "EXTERIOR" allowed
    source_ref: str | None
    confidence: Confidence

class Fixture(BaseModel):               # since v1.1.0 (change 001)
    id: str                             # "fixture_<n>"
    storey_id: str | None
    room_id: str | None                 # containing room if determined
    fixture_type: FixtureType           # see vocabulary.py
    position: tuple[float, float]       # box centre, in coordinate_space
    source_ref: str | None
    confidence: Confidence

class TextAnnotation(BaseModel):
    text: str
    bbox: tuple[float, float, float, float]   # x_min, y_min, x_max, y_max
    confidence: Confidence

class BlueprintAnalysis(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    source_format: InputFormat
    coordinate_space: Literal["PIXEL", "METRIC"]
    metric_available: bool              # True if real-world measures can be derived
    scale: Scale
    storeys: list[Storey]
    rooms: list[Room]
    openings: list[Opening]
    adjacency: list[tuple[str, str]]    # room-id pairs sharing a wall; sorted, unique
    texts: list[TextAnnotation]
    analyzer_version: str               # model/parser version, matches its model card
    warnings: list[str]
    fixtures: list[Fixture] = []        # since v1.1.0

# src/blueprint_qa/contracts/answer.py
class AnswerStatus(str, Enum):
    ANSWERED = "ANSWERED"; CANNOT_ANSWER = "CANNOT_ANSWER"
    NEEDS_CLARIFICATION = "NEEDS_CLARIFICATION"; UNSUPPORTED_QUESTION = "UNSUPPORTED_QUESTION"

class Answer(BaseModel):
    schema_version: str = "1.2.0"
    request_id: str
    status: AnswerStatus
    value: float | None                 # THE answer; non-null iff status == ANSWERED
    unit: Literal["count", "ratio", "boolean", "m", "m2", "m3", "ft", "ft2", "ft3"]
    confidence: Confidence
    evidence: list[str]                 # element ids from BlueprintAnalysis used
    explanation: str                    # short reasoning / reason for no value, in ParsedQuestion.language
    language: str                       # language of `explanation`
```

**Invariants:**
- `Answer.value` is a plain float. Counts are floats (`3.0`), and yes/no answers are exactly `1.0` (yes) or `0.0` (no) with `unit="boolean"`.
- `value` is **not rounded** inside the pipeline. Rounding for display is the presentation layer's job.
- Every answer carries its `unit`. Consumers MUST read `unit` and MUST NOT assume one.

### 4.3 Changing a contract or a shared file

- **R4.1** Only an agent in role A0 may edit `src/blueprint_qa/contracts/`. A0 follows this process too.
- **R4.2** To propose a change, create `docs/contract-changes/NNN-<title>.md` containing: the motivation, the exact diff, the affected roles, and whether it is breaking.
- **R4.3** **Additive, optional** changes cause a MINOR bump and need approval from A0 plus **1 human**.
  **Breaking** changes (rename, removal, type change, a new required field, removing an enum value) cause a MAJOR bump and need approval from **at least 2 of the 4 humans**.
- **R4.4** Consumers MUST ignore unknown optional fields. Producers MUST NOT emit fields that are not in the contract.
- **R4.5** A contract change, the regenerated `src/blueprint_qa/contracts/schema/*.json`, the updated §4.2 of this file, and the adapting code are merged **together**. `main` never disagrees with `src/blueprint_qa/contracts/`.

## 5. Error handling

- **R5.1** No exceptions cross a component boundary. Each entry point returns **its result contract or an `ErrorEnvelope`**.
- **R5.2** An invalid input is **not an error**. A1 returns `is_valid=False`, and A0 stops the pipeline. A2, A3 and A4 MUST NOT be called in that case.
- **R5.3** "I can't compute this" is **not an error**. A4 returns a non-`ANSWERED` status with `value=None`. **Never fabricate a number.**
- **R5.4** Error code registry (append-only; additions go through §4.3):

| Code | Stage | Retryable | Meaning |
|------|-------|-----------|---------|
| `EXTERNAL_API_TIMEOUT` | any | yes | External service did not respond within the configured timeout |
| `EXTERNAL_API_ERROR` | any | yes | Service returned 5xx or a malformed transport response |
| `EXTERNAL_API_AUTH` | any | no | Credentials missing or rejected |
| `EXTERNAL_API_QUOTA` | any | yes | Rate limit or quota exceeded |
| `LLM_OUTPUT_INVALID` | any | no | LLM output failed schema validation after all configured retries |
| `INVALID_INPUT` | any | no | Contract violation on input (an upstream bug) |
| `IFC_PARSE_FAILED` | VALIDATION / ANALYSIS | no | IFC file could not be parsed |
| `MODEL_LOAD_FAILED` | ANALYSIS | no | Weights missing or corrupt |
| `ANALYSIS_FAILED` | ANALYSIS | no | Recognition could not produce a result |
| `QUESTION_PARSE_FAILED` | QUESTION | no | Could not interpret the question at all |
| `REASONING_FAILED` | REASONING | no | Internal failure while computing |
| `INTERNAL_ERROR` | any | no | Anything else (always include a debug detail) |

## 6. Role-specific rules

### A0 — Orchestrator / Integration Lead

- **Entry point:** `src/blueprint_qa/orchestrator/pipeline.py :: run(request: PipelineRequest) -> Answer | ErrorEnvelope`
- MUST generate `request_id` and `received_at`.
- MUST call A1 first. Only when `is_valid=True` does it call A2 and A3 (concurrently), and then A4.
- MUST pass A1's normalized outputs (`plan_image` or `ifc_bytes`) to A3, never the raw upload.
- MUST validate every component's output against its contract before forwarding it. On a violation it returns `INVALID_INPUT` with `details.producer=<stage>`.
- MUST convert invalid-input results and `ErrorEnvelope`s into user-safe responses. `details` never reach the user.
- MUST NOT contain image-processing, NLP, IFC-parsing or calculation logic.
- Provides the shared LLM client wrapper in `src/blueprint_qa/common/llm.py` (§7.2) and the logger in `src/blueprint_qa/common/log.py`. Generates `src/blueprint_qa/contracts/schema/*.json`.

### A1 — Input Validator

- **Entry point:** `src/blueprint_qa/validation/validator.py :: validate(request: PipelineRequest) -> ValidationResult | ErrorEnvelope`
- MUST verify the real format from magic bytes or the file header, and return `FORMAT_MISMATCH` if it differs from `input_format`.
- **Every image input (PNG, JPEG and PDF) MUST be sent to the LLM API** to decide whether it is a house floor plan. Local checks run first only to reject files that cannot be decoded.
- **PNG/JPEG:** decode, apply EXIF orientation, convert to PNG and **never resize**, then classify with the LLM.
- **PDF:** a PDF MUST contain **exactly 1 page**. Otherwise return `MULTI_PAGE_PDF`. Render the page to PNG at a configurable DPI **[ASSUMPTION: 200 DPI]**, then classify it with the LLM.
- **IFC:** an IFC file is not an image, so it is validated locally with **no LLM call**. Check that it parses (e.g. with `ifcopenshell`), that the schema version is supported, and that it contains at least one `IfcSpace` or `IfcWall*`. Otherwise return `NO_SPATIAL_DATA`.
- `is_valid=True` requires confidence ≥ the configurable `validation.min_confidence` **[ASSUMPTION: 0.7]**. Below it, return `LOW_CONFIDENCE`.
- MUST map LLM output to `ValidationReason`. Raw LLM labels never leave `src/blueprint_qa/validation/`.
- MUST NOT analyse rooms or read the question.

### A2 — Question Interpreter

- **Entry point:** `src/blueprint_qa/question/interpreter.py :: interpret(request_id: str, question: str, locale_hint: str | None) -> ParsedQuestion | ErrorEnvelope`
- MUST hide the implementation behind a `QuestionProvider` adapter: `LlmQuestionProvider` (default), `MockQuestionProvider`, and optionally `LocalRuleProvider`. Swapping providers MUST NOT change the output.
- **Multilingual:** MUST accept questions in any language. English, German and Finnish are **required and tested**. Detect the language, set `ParsedQuestion.language`, and output canonical **language-independent** enums. No downstream component ever handles a natural-language question.
- MUST map synonyms in all supported languages to canonical `RoomType` values (e.g. "WC" / "Gäste-WC" / "vessa" → `TOILET`; "Schlafzimmer" / "makuuhuone" → `BEDROOM`). The LLM prompt gets the enum list, and the result is validated against it. Hard cases go into `src/blueprint_qa/question/synonyms/<lang>.yaml`, which is used as few-shot examples and for tests.
- Yes/no questions map to `EXISTENCE` or `COMPARISON`. Thresholds in `COMPARISON` are converted to SI by A2.
- If the question cannot be answered with a number (e.g. "where is the kitchen?"), return `Intent.UNSUPPORTED`. If it is ambiguous, set `clarification_needed`. Neither case is an error.
- MUST NOT receive the plan, and MUST NOT compute answers.

### A3 — Blueprint Analyzer

- **Entry point:** `src/blueprint_qa/analysis/analyzer.py :: analyze(validation: ValidationResult) -> BlueprintAnalysis | ErrorEnvelope`
- MUST be **question-agnostic**: it never receives the question and always extracts everything the contract supports.
- **Multilingual plans:** room labels and annotations may be in any language or abbreviation (e.g. Finnish `MH`, `OH`, `KPH`, `K`, `S`; German `WZ`, `SZ`, `Bad`). Map them to `RoomType`, and keep the original text verbatim in `label_text`. Mapping tables live in `src/blueprint_qa/analysis/labels/<lang>.yaml`.
- **Raster path (PNG/JPEG/single-page PDF):**
  - Coordinates are in the pixel space of the `PlanImage` received (`coordinate_space=PIXEL`). If the analyzer resizes internally, it MUST map results back.
  - A single image may still show several floors side by side. Detect this, create one `Storey` per floor, and add a warning.
  - Determine the scale if possible and record `Scale.source`. If the scale is unknown, set `metric_available=False` and leave all metric fields `None`. Never assume a scale.
  - `area_m2` SHOULD prefer a legible printed label (`LABEL_TEXT`) and otherwise be computed from the polygon and scale.
  - If a vision LLM is used for any sub-task, the rules in §7.2 apply, and coordinates it returns MUST be checked against the image bounds.
- **IFC path:**
  - `coordinate_space=METRIC`, `scale.source=IFC_MODEL`, `metric_available=True`.
  - Rooms come from `IfcSpace`, storeys from `IfcBuildingStorey`, and openings from `IfcDoor`/`IfcWindow`. Room types are mapped from names and properties using a mapping table in `src/blueprint_qa/analysis/ifc_mapping.py`.
  - IFC files MAY contain **multiple storeys**. Every room and opening MUST carry its `storey_id`, and all storeys MUST be listed in `storeys`.
  - Prefer IFC quantity sets (e.g. `Qto_SpaceBaseQuantities.NetFloorArea`, giving `area_source=IFC_PROPERTY`) over geometry computation, and record which was used.
- `adjacency` lists each pair once, sorted, and is consistent with `rooms`.
- Every ML model needs `models/<name>/MODEL_CARD.md` covering source, licence, training data, version and limitations. `analyzer_version` MUST match it. Large weights are not committed to git; use `models/fetch.py` with checksums.
- Anything uncertain goes into `warnings`.
- MUST provide a `--debug-overlay` CLI that draws the detections on the image (raster) or a 2D plan (IFC).

### A4 — Answer Reasoner

- **Entry point:** `src/blueprint_qa/reasoning/reasoner.py :: answer(question: ParsedQuestion, analysis: BlueprintAnalysis) -> Answer | ErrorEnvelope`
- **MUST compute `value` with deterministic code. No LLM may produce or modify the number.** An LLM MAY be used only to word the `explanation`.
- MUST NOT access the plan file or call A3. Its only knowledge of the plan is `BlueprintAnalysis`.
- Target resolution order: `storey` → `room_type` → `label` → `ordinal`. If several rooms match and `aggregation=SINGLE`, return `NEEDS_CLARIFICATION`.
- An intent that needs metric data while `metric_available=False` → `CANNOT_ANSWER` with an explanation. `COUNT` never needs metric data.
- `HEIGHT` and `VOLUME` need `height_m`. If it is missing, return `CANNOT_ANSWER`.
- `EXISTENCE` → `value = 1.0` if at least one matching element exists, else `0.0`, with `unit="boolean"`. `COMPARISON` → `1.0`/`0.0` from the computed measure.
  - **A `0.0` existence answer requires positive evidence.** If the relevant analysis is missing or untrustworthy (e.g. no rooms detected), return `CANNOT_ANSWER`, not `0.0`.
- **Storeys:** if the question names no storey and the plan has several, aggregate over **all storeys** **[ASSUMPTION]** (e.g. "total area" = the sum over all floors), and say so in `explanation`.
- `explanation` MUST be written in `ParsedQuestion.language`. `value`, `unit` and `status` are language-independent.
- Unit handling: the default output is SI (`m`, `m2`, `m3`); `count` is used for COUNT, `ratio` for RATIO and `boolean` for EXISTENCE/COMPARISON. Convert only if `requested_unit` is set (1 m = 3.28084 ft; 1 m² = 10.7639 ft²; 1 m³ = 35.3147 ft³).
- `Answer.confidence` ≤ min(question confidence, the confidence of the elements used).
- Every element used MUST be listed in `evidence`.

### A5 — QA & Integration Tester

- Owns `tests/fixtures/`, which holds valid and invalid samples **for each of PNG, JPEG, PDF and IFC**, with ground-truth `BlueprintAnalysis` JSON and question → expected float pairs (with tolerance). The source and licence of every fixture go in `tests/fixtures/SOURCES.md`.
- Question fixtures MUST cover **English, German and Finnish**: the same question in all three languages must give the same `ParsedQuestion` (apart from `language` and `original_question`). Plans with labels in each language MUST also be included.
- **Contract tests:** every component's output from the fixtures validates against `src/blueprint_qa/contracts/`.
- **End-to-end tests** through `orchestrator.run`, with LLMs mocked (§7.3), plus an opt-in `pytest -m live` suite that calls the real LLM API.
- **Numeric scoring:** a test passes if `abs(value - expected) <= max(abs_tol, rel_tol * abs(expected))`. Tolerances are configured per intent in `tests/fixtures/tolerances.yaml`: **COUNT, EXISTENCE and COMPARISON must be exact; all measured values use rel_tol = 5 %**.
- Maintains `docs/METRICS.md`: validator precision and recall, room detection F1, count accuracy, area error (MAPE), answer accuracy within tolerance, and the LLM token cost per request.
- MUST NOT fix production code. Report failures to the owning role as described in R2.2.
- Has **veto power** on merges that break contract or integration tests.

## 7. External services and LLM usage

### 7.1 General

- **R7.1** Each external service sits behind an adapter in the owning component.
- **R7.2** Timeouts and retry counts are configurable in `config/` (§3.9). Retry only on retryable errors, with exponential backoff, and never on 4xx except 429.
- **R7.3** A mock provider is mandatory and is the default in tests and CI. CI MUST NOT need network access or API keys.
- **R7.4** User data MUST NOT be sent to any service not listed in `docs/EXTERNAL_SERVICES.md`. Adding one requires human approval.

### 7.2 LLM rules (A1, A2, and A3 if a vision LLM is used)

- **R7.5** All LLM calls go through the shared wrapper `src/blueprint_qa/common/llm.py` (owned by A0). Components MUST NOT import a vendor SDK directly. This keeps a provider or model switch to a one-file change.
- **R7.6** The model ID and provider are set in `config/llm.yaml`, never hard-coded. Each component MAY have its own model setting.
- **R7.7** **Prompts are code.** They are stored as versioned files in `src/blueprint_qa/<component>/prompts/<name>.v<N>.md`, reviewed like code, and never edited in place once merged: a change means creating `v<N+1>`. The `provider` field records `llm:<model-id>:<prompt-name>@v<N>`.
- **R7.8** **Structured output only.** The LLM MUST be asked for JSON (using tool/function calling or structured-output features where available), and the response MUST be validated against a Pydantic model. If validation fails, re-ask up to a configurable number of times **[ASSUMPTION: 2]**, then return `LLM_OUTPUT_INVALID`.
- **R7.9** Use the lowest-randomness settings the provider allows (e.g. temperature 0) for every classification or extraction call.
- **R7.10** **Prompt-injection safety.** User text (the question, and text extracted from the plan) is always passed as clearly delimited data, never concatenated into instructions. An LLM response may never select code paths beyond the enum values in the contract.
- **R7.11** Log the model ID, prompt version, input/output token counts and latency for every call (A5 aggregates the cost). Never log the full prompt content at INFO level or above.
- **R7.12** Mocks for LLM calls use **recorded responses** ("cassettes") stored next to the tests and keyed by prompt version. Changing a prompt version requires re-recording its cassettes.

## 8. Logging and testing

- Use structured JSON logging via `src/blueprint_qa/common/log.py`. Every line includes `request_id` and `stage`.
- Do not log file bytes, full question text at INFO level or above, or secrets.
- Each component MUST have unit tests with ≥ 80 % line coverage **[ASSUMPTION]**, run with `pytest tests/unit/<component>`.
- Tests do not download anything at runtime.

## 9. Git workflow

- Branch naming: `<role>/<initials>/<short-description>`, e.g. `a3/ry/ifc-space-parsing`, where `<initials>` are those of the human who launched the agent.
- Commit messages: `[A3] Parse IfcSpace quantities` (role prefix, imperative mood).
